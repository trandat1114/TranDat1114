# Dev Random

Short engineering notes that start with a question.

The tone is intentionally less formal than an architecture document, but the standard is the same: separate observation from assumption.

## Draft topics

- Why SQL becomes hard
- What production bugs taught me
- Why distributed systems hurt
- Bad code is not always bad
- When microservices are the wrong answer
- Debugging a slow query
- Things I wish I knew before .NET
- Software is mostly integration
- The hidden cost of “just add a retry”
- A dashboard is not observability
- Why a queue does not automatically make a system reliable

## Writing rule

Start with a concrete problem.

Show the system.

Explain the trade-off.

End with what was learned—not with a generic motivational paragraph.
